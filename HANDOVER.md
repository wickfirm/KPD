## 4. How the key mechanisms work (reuse these)

- **Permissions** (`src/lib/permissions.ts`, the single source of truth): roles `ADMIN`, `EDITOR`, `CONTRIBUTOR`, `VIEWER`. Every server action starts with `requirePermission("…")` (`src/lib/auth.ts`), which re-reads the role from the database. `canViewPath` drives the middleware and the menu. Contributors: saves forced to Draft, edits to non-draft items refused (`mayEditContent`, `allowedStatus`). Controls are hidden by `data-requires="publish|delete"` plus `cms--no-publish` / `cms--no-delete` / `cms--readonly` classes on `.cms`. The cookie carries the role from sign-in, so menus lag a role change until re-login; actions do not. **Never use bare `requireUser()` for a write.**
- **Unsaved previews:** an action stores the form as one throw-away row in `site_settings` (`preview:section:<projectId>`, `preview:article:<id|new:<email>>`, `preview:page:<slug>`, `preview:home|invest:<email>`), expiring after 2 hours, read only by the session-guarded `/admin/preview/*` routes. Builders are shared with the real saves (`homeSettingsFromForm`, `buildStaticPageContent`, `paragraphBlocks`, `moduleContentFromForm`) so a preview cannot drift from a save.
- **Shared views:** `HomeView`, `InvestView`, `AboutView`/`LegacyView`/`ContactView` (`page-views.tsx`), `ArticleView`, `LegalPageView`, `DevelopmentView` render both the public page and its preview.
- **Loading/perf:** `requireUser()` is wrapped in React `cache()` (one users query per request); the layout queries the sidebar page list in parallel.
- **Styling:** `src/app/admin/admin.css` = tokens (`@theme`) + `cms-*` classes; new rules are appended in labelled blocks (identity layer, roles, loading, guide). Palette is neutral on purpose (the front-end is black/white/off-white with no accent). Font: Figtree via `next/font` (`src/app/admin/font.ts`), applied to the dashboard and login only.

**PR 3 — Right-to-left layout** (branch `locales/3-rtl`, stacked on PR 2: open it against `locales/2-cms` until PR 2 is merged)
- **What it is:** `public/locales/rtl.css`, one generated file, linked by the root layout on Arabic pages only, after every other stylesheet. It is the public stylesheets with every physical left and right mirrored: header (the button no longer sits over the logo), mega menu and mobile menu, footer, breadcrumbs, sub-navigation, forms and their pop-ups, news filters, timelines, the landing page. The delivered `site.css` is untouched. English and Japanese pages never request the file.
- **How it is built:** `node scripts/build-rtl-css.mjs` writes again every rule of `site.css`, `public.css`, `redesign-pages.css`, `sxs.css` and the two planner sheets that sets a side, mirrored where there is a side to mirror, then appends `scripts/rtl-manual.css` (hand-written; the draggable map on the home page, and two rules for text — below). **Never edit `rtl.css`:** `src/lib/rtl-css.test.ts` fails when it is out of date or holds a rule that is not limited to `html[dir="rtl"]`. Run the script again after any change to those stylesheets, including when the client delivers a new `site.css`.
- **Why it is built that way (the part that cost the time):** the delivered rules still apply, so the sheet cannot simply out-rank them. Every rule goes through `:where()`, which adds no weight, and wins only by coming last; whatever out-ranks a rule in English therefore still out-ranks it in Arabic. A rule that sets a side is written again even when it has nothing to mirror (`margin: 0`), so a later rule that cancels an earlier one still does. That set has to be **closed** — `top` and `bottom`, `margin-top`, a single border side included — because `inset: 0` sets them too: without them a repeated `inset: 0` beat the hero block's later `top: auto` and the title of the three legal pages ended up behind the header.
- **What is not mirrored:** photos (`object-position`), background images and sprites, flex order (the browser mirrors it), anything with no side to mirror. An exception goes in `rtl-manual.css`, with the page and what was seen.
